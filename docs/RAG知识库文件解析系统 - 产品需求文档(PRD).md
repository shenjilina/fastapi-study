# RAG知识库文件解析系统 \- 产品需求文档\(PRD\)

# 1\. 文档概述

## 1\.1 产品目标

搭建轻量化、可审计、高稳定的RAG知识库管理系统，支持用户创建知识库、上传文件、自动解析切片、向量入库、文档管理。核心差异化规则：**文件元数据永久留存不可删除，支持溯源审计；知识库、文档、切片支持软删除**。

## 1\.2 适用范围

后端接口开发、数据库设计、任务调度（文件解析/向量化/垃圾回收）、前端知识库管理页面、系统运维审计。

## 1\.3 核心约束

**文件表\(files\)数据永久不可删除**，禁止任何硬删除、软删除操作；磁盘文件删除仅做状态标记 \+ 清空路径字段。

- 知识库、文档、切片均采用软删除机制，数据可回溯

- 一个文件对应唯一有效文档，一个文档对应多个文本切片

- 所有解析、向量化流程异步化，支持失败重试、状态可追踪

# 2\. 业务角色与权限

|角色|权限范围|数据可见性|
|---|---|---|
|**普通用户**|创建知识库、上传文件、查看解析进度、查看文档、删除文档、管理个人知识库|可见自己创建的未删除知识库，以及其他用户公开且未删除的知识库；仅可操作自己创建的知识库|
|**系统/运维**|数据审计、查看已删除文档、查看磁盘已删除的文件元数据、清理无效向量数据|全局所有数据（含已删除、磁盘已删除）|

# 3\. 核心业务流程

## 3\.1 完整主流程

创建知识库 → 上传文件（仅保存files记录）→ 用户创建文档（写入documents记录，PENDING）→ 用户发起「开始解析」提交异步解析任务 → 文本切片生成 → 批量向量化入库 → 原子回写vector\_id与chunk\_count → 解析完成

## 3\.2 文件生命周期流程

**解析状态（files.status）**：UPLOADING\(上传中\) → UPLOADED\(上传完成\) → PARSE\_PENDING\(待解析\) → PARSING\(解析中\) → SUCCESS / PARSE\_FAILED。

**源文件存储状态（files.storage\_status）**：PRESENT\(磁盘文件存在\) → PHYSICAL\_DELETED\(磁盘文件已删除，记录保留)。该状态与解析状态独立，不得覆盖解析结果。

上传成功后保持UPLOADED；用户手动发起「开始解析」时才切换至PARSE\_PENDING并入队。重试统一从PARSE\_FAILED切换至PARSE\_PENDING。

用户取消上传时，files.status改为UPLOAD\_CANCELLED，已上传的临时文件立即删除，storage\_status改为PHYSICAL\_DELETED；files记录仍永久留存且不创建documents记录。

## 3\.3 文档解析失败流程

解析异常 / 文件损坏 / 向量化失败 → files.status=PARSE\_FAILED、documents.parse\_status=FAILED → 记录error\_msg → chunk\_count置0 → 软删除本次产生的chunks并异步清理已写入的向量 → 支持用户重新触发解析重试。

## 3\.4 资源删除流程（差异化核心）

1. **删除文档**：文档软删除 → 切片软删除 → 异步清理向量库；仅在向量实际清理成功后标记vector\_cleaned=1，失败时保持0并进入重试队列。若源文件仍存在，将files.status回退为UPLOADED，允许后续创建新的有效文档并重新解析

2. **删除磁盘文件**：仅删除服务器物理文件 → 清空stored\_filename与storage\_path → storage\_status改为PHYSICAL\_DELETED → files数据库记录永久保留，files.status保持原解析状态

3. **删除知识库**：知识库软删除，关联文件、文档、切片数据全部保留，用于审计溯源

# 4\. 状态机定义（枚举规范）

## 4\.1 文件状态 files\.status

|枚举值|前端标签色|含义|
|---|---|---|
|UPLOADING|蓝色|文件上传中|
|UPLOAD\_CANCELLED|灰色（置灰）|用户已取消上传；仅保留审计记录|
|UPLOADED|灰色|上传完成，等待发起解析|
|PARSE\_PENDING|橙色|待解析（任务就绪排队中）|
|PARSING|蓝色|解析任务执行中|
|SUCCESS|绿色|解析与向量化均已成功|
|PARSE\_FAILED|红色|文件解析失败|

## 4\.2 源文件存储状态 files\.storage\_status

|枚举值|前端标签色|含义|
|---|---|---|
|PRESENT|无单独标签|服务器磁盘文件仍可读取|
|PHYSICAL\_DELETED|灰色（置灰）|磁盘物理文件已删除，数据库记录留存|

## 4\.3 文档解析状态 documents\.parse\_status

|枚举值|前端标签色|含义|
|---|---|---|
|PENDING|灰色|待解析|
|PARSING|蓝色|解析切片中|
|SUCCESS|绿色|解析切片成功|
|FAILED|红色|解析失败|

## 4\.4 知识库状态 knowledge\_bases\.status

|枚举值|前端标签色|含义|
|---|---|---|
|ACTIVE|绿色|正常可用|
|DISABLED|红色|禁用，不可上传文件、不可解析|
|ARCHIVED|灰色|归档，只读不可操作|

状态变为DISABLED或ARCHIVED后，后端拒绝新的上传、解析和重试请求；已在PARSING的任务允许完成，尚未开始的PARSE\_PENDING任务取消入队并回退为UPLOADED/PENDING，待知识库恢复ACTIVE后才能再次提交。

# 5\. 数据库表设计（最终版）

## 5\.1 知识库表 knowledge\_bases

存储用户创建的知识库基础信息，支持私有/公开权限，支持软删除。

|字段|类型|默认值|说明|
|---|---|---|---|
|id|bigint unsigned|自增|主键，知识库ID|
|owner\_id|bigint unsigned|\-|创建者用户ID|
|name|varchar\(255\)|\-|知识库名称|
|description|text|null|知识库描述|
|visibility|enum|PRIVATE|PRIVATE私有 / PUBLIC公开|
|status|enum|ACTIVE|知识库状态|
|created\_at|datetime\(6\)|当前时间|创建时间|
|updated\_at|datetime\(6\)|自动更新|更新时间|
|deleted\_at|datetime\(6\)|null|软删除时间|

## 5\.2 文件表 files（核心特殊表）

存储所有上传文件元数据，**永久不可删除**，仅可标记磁盘删除状态，用于审计溯源。

|字段|类型|默认值|说明|
|---|---|---|---|
|id|bigint unsigned|自增|文件主键ID|
|owner\_id|bigint unsigned|\-|上传用户ID|
|knowledge\_base\_id|bigint unsigned|\-|所属知识库ID|
|filename|varchar\(255\)|\-|原始文件名|
|stored\_filename|varchar\(255\)|null|服务端文件名，磁盘删除后置空|
|storage\_path|varchar\(512\)|null|存储路径，磁盘删除后置空|
|file\_type|varchar\(64\)|null|文件类型（pdf/docx/markdown等）|
|mime\_type|varchar\(128\)|null|MIME类型|
|file\_size|bigint unsigned|0|文件字节大小|
|file\_md5|char\(32\)|\-|文件MD5，用于去重|
|status|enum|UPLOADING|文件全生命周期状态|
|storage\_status|enum|PRESENT|源文件存储状态；物理删除后为PHYSICAL\_DELETED|
|created\_at|datetime\(6\)|当前时间|创建时间|
|updated\_at|datetime\(6\)|自动更新|更新时间|

**特殊规则**：无deleted\_at字段，记录永久留存；禁止任何DELETE SQL操作files表。

## 5\.3 文档表 documents

文件解析后的文档主体，直接保存所属知识库ID；创建时必须校验该ID与关联文件所属知识库一致。

|字段|类型|默认值|说明|
|---|---|---|---|
|id|bigint unsigned|自增|文档ID|
|file\_id|bigint unsigned|\-|关联文件ID；有效document与文件一对一，历史软删除document可保留多条|
|knowledge\_base\_id|bigint unsigned|\-|所属知识库ID；创建时必须与关联文件的知识库ID一致|
|title|varchar\(255\)|\-|文档标题|
|description|text|null|文档描述|
|chunk\_count|int unsigned|0|切片总数，解析失败置0|
|parse\_status|enum|PENDING|解析状态|
|error\_msg|text|null|解析失败日志|
|vector\_cleaned|tinyint|0|向量是否已回收（0未清理 / 1已清理）|
|file\_size|bigint|0|冗余文件大小，优化查询|
|created\_at|datetime\(6\)|当前时间|创建时间|
|updated\_at|datetime\(6\)|自动更新|更新时间|
|deleted\_at|datetime\(6\)|null|软删除时间|

**约束**：一个file在任一时刻最多存在一条`deleted_at IS NULL`的documents记录。数据库应为`file_id WHERE deleted_at IS NULL`建立部分唯一索引，不能仅依赖`(file_id, deleted_at)`联合唯一索引。文档软删除后，下一次解析可创建新的有效documents记录。

## 5\.4 文档切片表 chunks

存储文档分割后的文本片段，RAG检索核心数据表，文档解析成功后批量生成。

|字段|类型|默认值|说明|
|---|---|---|---|
|id|bigint unsigned|自增|切片ID|
|document\_id|bigint unsigned|\-|关联文档ID|
|chunk\_index|int unsigned|\-|切片序号|
|content|longtext|\-|切片原文|
|vector\_id|varchar\(128\)|null|向量库唯一ID|
|created\_at|datetime\(6\)|当前时间|创建时间|
|deleted\_at|datetime\(6\)|null|软删除时间|

## 5\.5 审计操作表 audit\_logs

记录上传、取消上传、解析状态迁移、重试、知识库状态变更、文档软删除、源文件物理删除和向量清理等操作。审计记录仅追加，不提供业务侧删除能力。

|字段|类型|默认值|说明|
|---|---|---|---|
|id|bigint unsigned|自增|审计记录ID|
|operator\_id|bigint unsigned|null|操作者用户ID；系统任务为空|
|action|varchar\(64\)|\-|操作类型|
|target\_type|varchar\(32\)|\-|目标类型（knowledge\_base/file/document/chunk/vector）|
|target\_id|bigint unsigned|\-|目标ID|
|request\_id|varchar\(64\)|null|请求或任务唯一标识，用于幂等追踪|
|detail|json|\-|操作前后状态、失败原因等脱敏摘要|
|created\_at|datetime\(6\)|当前时间|记录时间|

# 6\. 核心数据生成时机

## 6\.1 chunks 切片数据生成时机

1. 文件上传完成后仅创建files记录，files.status变为 **UPLOADED**；用户调用创建文档接口后才创建一条parse\_status=**PENDING**的有效documents记录，随后可发起解析任务

2. 用户调用开始解析接口后，files.status改为**PARSE\_PENDING**；任务开始时files.status与documents.parse\_status同时改为 **PARSING**

3. 读取本地文件，执行文本分割算法，生成文本片段

4. 在同一任务批次中暂存并批量写入chunks表数据（此时vector\_id为空）

5. 逐一对切片内容做Embedding向量化，写入向量库

6. 全部向量写入成功后，事务性回写vector\_id，更新documents\.chunk\_count、documents.parse\_status=SUCCESS与files.status=SUCCESS

解析失败：不得保留可检索的有效chunks数据；已生成的chunks软删除、已写入的向量进入清理队列，chunk\_count=0，写入error\_msg。

## 6\.2 数据一致性规则

- 1 file → 最多1条有效document（见5\.3约束）；历史软删除document仅供审计，不参与业务查询与检索

- 1 document → N chunks

- 文档知识库归属一律通过file关联获取，禁止单独赋值

# 7\. 前端页面与交互规范

## 7\.1 页面整体架构

系统采用**单页左右布局**，整合原知识库列表页与详情页。无独立路由跳转，所有操作在同一页面完成。

**左侧：知识库列表栏（固定宽度 320px）**

展示知识库列表、搜索筛选、快捷操作图标

**右侧：知识库详情区（自适应宽度）**

展示选中知识库的信息、文件列表、操作按钮

**核心交互逻辑**：页面加载后，若列表非空则默认选中第一项并加载右侧详情；列表为空或当前页无选中项时展示空状态。点击左侧列表任意项，实时切换右侧详情内容，无页面刷新；切换时终止上一轮状态轮询，按新知识库是否存在进行中任务决定是否开启轮询。

## 7\.5 状态轮询与实时刷新规则

- 右侧详情区存在UPLOADING、PARSE\_PENDING或PARSING状态的文件时，前端每**3秒**轮询一次列表接口

- 切换左侧知识库时，**立即终止**上一轮轮询定时器，再开启新轮询

- 所有文件均为终态（SUCCESS / PARSE\_FAILED / UPLOAD\_CANCELLED）时，**停止轮询**，仅保留手动刷新；PHYSICAL\_DELETED是独立存储状态，不决定是否轮询

- 页面切到后台（visibilitychange）时暂停轮询，切回前台恢复

# 8\. 后端接口能力清单

## 8\.1 知识库接口

1. **创建知识库**：入参名称、描述、可见性；返回知识库ID

2. **编辑知识库**：修改名称、描述、公开/私有状态

3. **知识库列表查询**：分页、搜索、状态筛选、时间筛选；默认过滤deleted\_at

4. **知识库状态修改**：启用/禁用/归档

5. **知识库软删除**：仅设置deleted\_at，保留关联所有文件、文档数据

6. **知识库详情查询**：基础信息 \+ 文件统计 \+ 文档统计

## 8\.2 文件接口

1. **文件分片/整体上传**：返回文件ID、实时状态

2. **文件列表查询**：根据知识库ID查询、状态筛选、分页

3. **文件详情查询**：文件元数据、归属信息、解析关联文档信息

4. **磁盘文件物理删除**：仅删除服务端文件、清空stored\_filename与storage\_path、修改storage\_status=PHYSICAL\_DELETED，**不删除数据库记录且不改写files.status**

5. **文件状态更新**：同步上传、解析全流程状态；状态迁移须校验当前状态，避免乱序回写

## 8\.3 文档解析接口

1. **触发解析任务**：手动发起文件解析、异步调度任务

2. **重试解析任务**：针对失败文档重新切片、向量化

3. **文档列表查询**：关联知识库、关联文件、状态筛选

4. **文档详情查询**：解析信息、切片数量、错误日志、向量清理状态

5. **文档软删除**：软删除文档 → 联动软删除切片 → 异步清理向量数据；仅清理成功后更新vector\_cleaned=1，源文件仍存在时将files.status回退为UPLOADED

## 8\.4 切片与向量接口

1. **切片列表查询**：根据文档ID查询所有切片内容、分页预览

2. **向量垃圾回收**：手动/自动清理无效向量、更新vector\_cleaned状态

3. **切片数据校验**：后台巡检核对切片数量与文档chunk\_count一致性

## 8\.5 运维审计接口

1. **全局文件记录查询**：含磁盘已删除文件、历史归档记录

2. **全局文档记录查询**：含已软删除文档

3. **异常任务统计**：解析失败、向量回收失败数据统计

4. **审计日志查询**：按操作者、目标、操作类型、时间范围查询audit\_logs

# 9\. 前后端数据联动规则

- **前端轮询**：右侧详情区解析中状态3s轮询一次，切换左侧列表时终止上一轮、开启新轮询

- **状态统一**：前后端状态枚举完全一致，前端通过统一字典映射渲染，不写死文案

- **数据过滤**：知识库业务列表过滤deleted\_at；文件列表始终保留files记录，默认仅关联有效documents；文档与切片业务查询过滤deleted\_at。运维页面可显式包含已删除记录

- **缓存规则**：知识库列表可缓存，解析状态实时刷新不缓存

- **并发安全**：后端对同一文件解析加任务锁，禁止重复触发；前端按钮在处理中置灰双重保障

# 10\. 非功能约束

## 10\.1 前端非功能约束

- **体验约束**：所有异步操作必须有加载状态、成功/失败反馈，无空白卡顿

- **校验约束**：前端前置校验文件格式、大小、空表单，减少无效接口请求

- **权限约束**：按钮级权限控制，无权限操作隐藏按钮，禁止弹窗绕过权限

- **兼容约束**：适配主流浏览器，列表、弹窗、进度展示样式统一

## 10\.2 后端非功能约束

- **审计合规**：所有上传文件元数据永久留存，支持全链路溯源

- **数据安全**：磁盘文件删除后清空数据库存储路径，防止路径泄露

- **容错性**：解析、向量化失败可重试，状态可追踪，日志完整记录

- **数据干净**：软删除统一隔离业务数据，不物理删除核心业务数据

- **并发安全**：禁止同一文件重复触发解析，后端做任务锁控制

- **接口幂等**：上传、解析、删除接口支持幂等，避免重复生成数据

## 10\.3 运维规则

- 定时巡检任务：每日核对文档切片数量一致性、清理无效向量数据

- 日志留存：上传日志、解析日志、删除操作日志以audit\_logs永久留存；错误详情只写入受控字段，不记录文件正文、令牌或其他敏感信息

- 数据溯源：可通过文件MD5、用户ID、时间追溯所有操作记录

# 11\. 风险规避

## 11\.1 前端风险规避

- **状态展示错乱**：前后端统一枚举字典，前端不写死状态文案，统一映射渲染

- **重复操作**：解析/上传过程中按钮置灰锁定，禁止重复点击

- **数据遗漏**：列表按分页查询，切换分页后根据当前页重新选择知识库；搜索与状态筛选组合生效，不将分页误表述为全量加载

- **权限越权**：前端页面权限\+按钮权限双层控制，配合后端接口鉴权

## 11\.2 后端风险规避

- **知识库与文档归属不一致**：去除文档冗余kb字段，通过文件关联获取

- **文件数据丢失**：禁用文件数据库删除，永久留存审计

- **重复切片**：有效文档唯一约束与同一文件任务锁共同生效；失败批次的切片和向量清理完成后才允许重试批次写入

- **向量垃圾数据**：vector\_cleaned标记兜底回收，定时巡检清理

- **任务堆积**：异步任务超时机制、失败重试次数限制、死任务重置
